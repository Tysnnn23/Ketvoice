# Ketvoice project workflow

- Autonomy: do not ask the user for permission before making changes. Proceed directly with edits, tests, commits, pushes and releases that the workflow below already calls for. Ask first only for actions with a very serious impact (danger ≥ 8/10), for example: irreversible data loss, deleting or overwriting published releases/tags, force-pushing or rewriting shared history, rotating or exposing signing keys/credentials, weakening server-enforced authorization, or deleting user accounts/catalog data.
- User preference: after completing and validating requested app changes, commit and push the sources to GitHub `main` and publish the corresponding version with both signed mobile and Quest APKs, notes, checksums and validation metadata. Do not wait for another "push" request. If validation, authorization or publication is blocked, report the blocker instead of claiming publication.
- Preserve concurrent user changes and upstream commits. Never force-push or overwrite an existing published release/tag. Keep old releases intact; historical APKs 1.2.0–2.3.0 must not be published.
- SDKs, emulator images, caches, signing keys and credentials do not belong in Git. Stage installable APKs as GitHub release assets, not Git blobs. Verify uploaded downloads against local SHA-256 hashes.
- Quest remains a landscape 2D window with the mobile style: artwork/controls left, lyrics or queue right. Keep the French default, 11 interface languages, Canvas controls, karaoke and reduced-motion support.
- Publishing/editing authorization must be server-enforced for the verified `konnektsupport@gmail.com` account. Audio replacement and metadata edits are only for that account's imported publications. Visual overrides are also allowed for existing catalogue items (owner, 2026-11-14: « Il y'a un problème je veut aussi pouvoir modifier les photo/fan art d'artiste existant et album et musique aussi ! »): the verified account may lay its own cover, Canvas or artist photo over a catalogue title, album or artist. They are stored as separate, restorable overrides (`ketvoice_media_overrides`, written only through `ketvoice-content`); the catalogue data itself is never modified or deleted.
- Automix (owner, 2026-11-14: « je veux que on planifie une toute nouvelle fonctionnalité incroyable L'AUTOMIX comme spotify et apple music », then « Oui tout me va […] fait tout sa le meilleur automix possible »): mixing titles into each other is back as a new feature in `app/.../automix/`, switched on from the queue or Settings and off by default. The AutoMix of 3.0.6, removed in 3.10.0, stays removed: its engine files are not restored and its settings keys (`automix`, `automixAutoFade`, `automixFadeSeconds`, `automixPerformance`) stay retired; the new switch is stored as `automixOn`. Since 5.2.0 the feature is called **Ketmix (BETA)** everywhere a listener reads it (owner, 2026-11-15: « fait en Le Ketmix (BETA) la meilleur feature d'automix de toute app musicale », and its switch belongs at the left end of the bar under the transport, not over the queue list); the code keeps the `automix` package and names. Its analysis setting is stored as `ketmixAnalysis` (the retired `automixPerformance` is not reused); since 5.3.0 also `ketmixLoops` (a title on repeat mixed into itself, owner 2026-11-15: « fait en sorte que meme les sons joue en boucle peuvent se mixer aussi »), `ketmixStyle` and `ketmixHaptics`.
- R8 (owner, 2026-11-15, about 5.8.0: « ketvoice ne marche plus du tout et bug énormément … les musiques télécharger et en streaming ne se lance plus »): 5.8.0 shipped the release build with R8, never run on a device, and the owner found playback broken and the app stuttering; 5.8.1 builds without it again (`isMinifyEnabled = false`). The real cause, found in 5.8.2 by `AudioChainPlaybackTest` (a file played through the service's audio chain under Robolectric), was a bulk copy in `ReverbAudioProcessor` that put Media3's shared empty buffer into itself; keep that test, and run it after any change to an audio processor. Do not switch R8 back on unless a release APK built with it has been installed and played on a device first; `app/proguard-rules.pro` is kept for that attempt. New settings keys of 5.8.0: `livingArtwork` and `autoOfflineFavorites`. The Liquid Glass launcher icon (since 5.8.1) is the owner's photographed glass K (`drawable-*dpi/ic_launcher_liquid_fg.png` on a black ground).
- 5.9.0 (owner, 2026-11-16, chosen from proposals): new settings keys `coverAccent` (off: the chosen accent rules unless the listener turns it on) and `volumeLeveling` (off by default; `LevelingAudioProcessor` sits between `DeckMixProcessor` and `ReverbAudioProcessor`, keep `AudioChainPlaybackTest` covering it); yearly listening for Wrapped is stored as `years` in the `listening-history` preferences. The ten-band equalizer keeps `equalizerGains`; five-band values of earlier versions are converted by `EqualizerProfile.normalize`. The owner removed the For you card and the four shortcut tiles from Home (keep `Votre semaine`).
- 5.9.1 (owner, 2026-11-16): settings keys `coverBackground` (off by default) and `ketmixStems` (experimental, off by default; real-time vocal cut through `DeckAutomation.vocalCut`, see `Stems` in `DeckDsp.kt`; no stem files are computed or stored — on-device Demucs-style separation was not added). Custom lyrics files live in `filesDir/custom-lyrics` with their index in the `custom-lyrics` preferences. Cover colours for pages, accents and the player all come from `theme/CoverColors.kt`. Discord sessions are restored on start from `DiscordTokenStore`.
- 5.9.2 (owner, 2026-11-16: « creer aussi un mode performance donc les effets sont toujours visible mais certains truc invisible ou peu visible sont diminués »): `highPerformanceMode` no longer turns glass off — it keeps the blur and drops refraction, per-line lyric blur, half the artwork-flow frames and image crossfades; keep visible effects (Canvas, glass) in it. Lyrics videos are encoded on the device by `util/LyricVideo.kt` (MediaCodec surface input, frame-count timestamps); the encoder cannot run under Robolectric, so only its layout (`previewFrame`) and timing are host-tested.
- 5.10.0 (owner, 2026-11-16: « La séparation doit etre reel … il est optionnel ce téléchargement et il doit être optimisée pour que sa soit fait une seule fois »): Ketmix separates voices for real with the optional Spleeter 2-stems model, converted to LiteRT (float16 weights) by `.github/workflows/publish-stem-models.yml` and published as the `ketmix-stems-v1` prerelease (never the latest release; the in-app updater ignores its non-version tag). Its SHA-256 and sizes live in `tools/stems/expected.sha256` and `stems/StemModel.kt` (a test keeps them equal); never republish over that tag — a new model is a new tag. `stems/` holds the pure-Kotlin STFT/resampler/separator (host-tested, and against sherpa-onnx with `KETVOICE_STEM_REF` locally); each title part is separated once and stored as a 4-bit mask in `filesDir/stems/masks`, applied to a fresh capture of the deck's own sound, so the stored data stays tiny. Decks read `DeckControl.stem`; without the model the 5.9.1 band cut remains. New settings keys `ketmixStemsCharging` and `lyricVideoSound`. Playback: network losses resume the same stream (`NetworkRecovery`), `PlaybackJournal` keeps events and Android's exit reasons on the device; manufacturer battery screens are listed in `BackgroundPlayback.vendorIntents` (declared in the manifest's `<queries>`).
- 5.11.0 (owner, 2026-11-16, chosen from proposals: « Anticipe a l'avance ce mix rend le encore plus rapide et se charge des le lancement d'un son et le mix devient intelligent »): Ketmix prepares from 4 s into a title (`Automix.prepare`: its ending, then the intro and ending of the next `LOOKAHEAD` = 3 titles, 1 on a metered network), prepares downloaded files while charging (`stems/StemLibrary.kt`, at most 300 titles because `AnalysisStore` keeps 900 entries), mixes for real on a manual skip (`Automix.skipMix`, falls back to the 5.9.0 fade), reads where a title sings from its separation (`VoiceActivity`, stored in separations of format `KVS2`; `KVS1` files of 5.10.0 stay readable), may play the incoming voice alone over the outgoing instrumental (`Mashup`, `DeckAutomation.vocalSolo`, `StemAudio.vocals`) and, in shuffle, moves the best tempo/key match next (`SmartQueue`; never in front of a title added with « Lire ensuite », see `Player.pinnedNext`). New settings keys `ketmixSmartQueue` and `ketmixLibrary` (both on by default). Ketmix still never changes a deck's speed while it is heard. Ketmix exits stay within a title's ending: a title is never left before its last sung part, even though breaks are known.
- 6.0.0 Beta (owner, 2026-11-16: « Continue d'améliorer la séparation et Ketmix », then « Publie », « met 6.0.0 Bêta »): a second, optional separation model, UVR-MDX-NET Voc FT, published by `.github/workflows/publish-stem-model-hq.yml` as the `ketmix-stems-v2` prerelease (pins in `tools/stems/expected-hq.sha256` and `StemModel.kt`; onnx2tf rewrites its input ONNX in place, so the source digest is checked before conversion). `stems/Uvr.kt` reproduces sherpa-onnx's UVR pipeline (UvrTest compares with it locally through `KETVOICE_UVR_REF`); its voice is stored as the usual 4-bit mask with the model's quality (format KVS3). New key `ketmixStemsQuality` (0 automatic, 1 always the best, 2 always quick). Quality was measured locally on MUSDB18-HQ excerpts (CC BY-NC-SA, never committed; `tools/stems/evaluate_*.py`). The owner's redesign (Ket 27 only, Cascade only, tablet layouts, menus, voice level) shipped in 6.0.0 Beta 2.
- Ket 27 (owner, 2026-11-15: « ajoute un nouveau mode … Ket 27 (Alpha) … une interface COMPLÈTEMENT Ios27 »; 2026-11-16: « maintenant ket27 est le theme principal l'ancien n'existe plus et pour les paroles aussi seul le mode cascade est disponible »): since 6.0.0 Beta 2 Ket 27 is Ketvoice's only interface and Cascade the only lyrics style. The `ket27` and `lyricsStyle` settings are retired (never read, written or backed up; `RetiredInterfaceSettingsHostTest`); do not bring back a classic path or a style choice. Everything follows `theme/Ket27.kt`; Material alerts, text buttons, spinners, progress bars and snackbars are replaced by `AppAlertDialog`, `KetTextButton`, `ActivitySpinner`, `KetProgressBar`, `KetSnackbar` — use those for new UI. It ships Inter (SIL OFL, `docs/licenses/Inter-OFL.txt`) because San Francisco cannot be redistributed. Shared pieces: `ui/common/SpringSheet.kt` (detents; off on Quest), `ui/motion/SymbolEffects.kt`, `ui/player/PlayerPresentation.kt` (`PlayerDismiss`, `travelFromMini`), `ui/common/Ket27Page.kt`; motion snaps under `Motion.reduced`.
- Menus (owner, 2026-11-16: « Le sous menu que tu a fait en mode ket27 doit remplacer le menu de base … l'ancien menu s'affichera que en cliquant sur "More" »): `GlassContextMenu` is the menu of a title, from a long press and from every "…" button (`RowAnchor.modifier` on the button, `RowAnchor.open(track)`; opened without an anchor it is centred). The full `TrackMenuSheet` opens only from its *Plus*/More item. The queue keeps its long press for selection.
- Tablets and large windows (owner, 2026-11-16: « les layouts devraient etre mieux que ceux d'apple music sur ipados »): `ui/adaptive/` and `ui/tablet/`. Layout follows the window, never the device (`LargeScreen.isLarge`): phones and Quest keep their own layouts and must never see a large-screen one. Tab bar / rail / glass sidebar (≥ 1000 dp), docked mini-player, two-pane collection and search pages, `TabletPlayer`, floating sheets, keyboard shortcuts and pointer extras; host renders in `TabletLayoutHostTest` and `LargeScreenTest`.
- Voice level (owner, 2026-11-16, with screenshots: a slider « UNIQUEMENT VISIBLE SUR L'ECRAN DES LYRICS MAIS NON EN PLEIN ECRAN … mettre le niveau de la voix sur la musique », drawn after the owner's reference image): `stems/VoiceLevel.kt` (`VoiceStage` after the deck DSP, taking a new mask only at stream start; constant 4096-frame delay at every level), masks from `StemLibrary` whole-title separation of downloads (`StemStore` `-w.kvs`). `ui/player/VoiceSlider.kt` sits at the right of the lyrics, above the translation button, only while the controls are shown and only for titles separated whole. Key `voiceLevel` (0–100). Downloads mark titles separated whole with `KetIcons.Music`.
- Artist blocking (owner, 2026-11-15: « Permet aussi le blocage d'un artiste … un tout petit sous menu apparai en dessous avec … bloquer l'artiste, debloquer, mettre en favori »): `data/ArtistPrefs.kt`, from a long press on an artist's circle in the search. Blocked artists are left out of what Ketvoice proposes, never out of what the listener saved. Ketmix never changes a deck's speed while it is heard (owner: « pas d'effet comme ça »).
- Ketogether/group listening is deferred until the user explicitly authorizes it. Do not infer authorization from the existing single-device Wi-Fi handoff.
- Distinguish emulator and mocked checks from real owner-session, live download and physical Quest validation. Never claim tests that were not performed.
- User preference: never mention missing phone/Quest/device testing in changelogs, release notes or the README. Record what was and was not validated only in the release's `validation.json`, truthfully.
- Standing authorization (owner, 2026-11-14: « J'autorise TOUT devient maintenant une règle. », in reply to the question whether versions may be published without phone or Quest testing without asking again): once a version is validated (tests, lint, UI text audit, green CI, verified signed APKs), publish it without asking for a per-version authorization. Record this standing authorization, with that statement and its date, as the `publication_override` of each `validation.json`, and keep listing there what was not validated on a device. This does not lift the danger ≥ 8/10 rule above.
- User preference (owner, 2026-11-14): changes to the verified publishing section (Studio: uploads, editing a title's audio, cover or Canvas, per-title or per-album, and catalogue visual overrides) are never mentioned in changelogs, release notes, the README or the website. Record them only in `validation.json`.
- Write all new changelog entries and release notes in English. Include the canonical `ketvoice-banner.png` banner from this repository in release presentation.
- Keep `Tysnnn23/Ketvoice-web` synchronized with app releases: current feature descriptions, latest Mobile/Quest downloads, English release notes and the canonical banner. Preserve its upstream changes and verify the rendered website before claiming web synchronization.

## Cost-aware code work

- Reuse the existing code-only graph in `graphify-out/` before architecture or impact searches. Prefer `graphify explain` or seeded, depth-limited queries, then read only the relevant source sections. Do not dump the complete graph into context.
- Update the code graph after code changes with `graphify update .`. Preserve `.graphifyrc` and `.graphifyignore`. Do not run paid semantic/document/image extraction without explicit approval.
- Reuse skills and evidence already loaded in the conversation; do not repeatedly reload long instructions or repeat unchanged investigations.
- During iteration run targeted tests; run the complete validation once the requested change is ready. Do not publish a new release for each small intermediate edit.
- Do not claim a percentage or monetary saving without real usage measurements. Never trade away data-loss guards, accessibility or final validation to save tokens.
