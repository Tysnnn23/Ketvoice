# Ketvoice 3.17.0

![Ketvoice](https://raw.githubusercontent.com/Tysnnn23/Ketvoice/main/ketvoice-banner.png)

## Artist page

- The hero artwork now uses an **intelligent full-bleed scale**: it always covers the whole header (slight overscan plus side feathers), so the visible vertical "end of image" lines are gone. Portrait and wide banners are handled by the same crop instead of a fitted portrait with flat bands.
- The refresh button now performs a **real reload**: it drops the cached artist page and the cached portrait/background/signature for that artist, then fetches the current server version. A new **share** button sits next to it and produces a real link (the artist's YouTube Music channel when the id is known, otherwise its artist search page).

## Playlists and collections

- **Playlists** have a share action that produces a stable Ketvoice link with the playlist name and track count. **Albums** now share their own YouTube Music page when it exists, and playlists/collections use the Ketvoice landing page.
- **Liked songs, recently played, all tracks and downloads** now use the same presentation as a playlist/album: blurred ambience, large artwork or a 2×2 mosaic, title, count and duration, then the same **Écouter / Aléatoire** actions plus **Partager** and **Actualiser**. Downloads keep their progress bar, per-track actions and "prepare an offline capsule" entry.

## Discord — root cause fixed

- The OAuth callback was only handled in memory. If Android recreated Ketvoice while the browser/WebView was in front, the pending state and PKCE verifier were lost, so the redirect returned to an app that silently ignored it: "authorized, back in the app, still not connected".
- The pending authorization is now **persisted** (state + verifier, five-minute validity, erased on handling) and recovered in the callback.
- Ketvoice now performs the **authorization-code exchange itself** with PKCE on a worker thread (no client secret), saves the encrypted refresh token, feeds the access token to the SDK and marks the account linked even if the presence client cannot start; the SDK exchange remains the fallback. Callback parsing accepts the HTTPS bridge, the `discord-<id>` scheme and `ketvoice://discord`, with a strict state check.

## Progressive playback

- The quality switch already restarts at the same position when the media session refuses the internal command; the next two queue items are still prefetched after playback starts, and failed sources are tried in order without a pre-request that could burn a one-shot URL.

## Validation

- Automated (299 debug / 254 release tests per variant): PKCE S256 against the RFC 7636 vector, authorization URL contents, public-client exchange form, token/error parsing, all accepted and forged callback forms, share-link builders, artist-cache invalidation, and the collection hero rendering (screenshot + actions).
- Live Discord check: a deliberately invalid code sent to `https://discord.com/api/oauth2/token` with the app's client id and redirect returned **HTTP 400 `invalid_grant` — Invalid "code"**, which proves the endpoint, client id, redirect and request shape are correct without logging in an account.
- **Not validated**: the real Discord consent with your account, and playback/downloads on a physical phone. No emulator was used.
