# Ketvoice 4.8.1

![Ketvoice](https://raw.githubusercontent.com/Tysnnn23/Ketvoice/main/ketvoice-banner.png)

## Device language by default

- On first launch Ketvoice now starts in the device language whenever one of its eleven interface languages matches it (Spanish, German, Portuguese, Italian, Russian, Chinese, Japanese, Korean, Hindi, English or French). An unsupported device language falls back to English.
- The per-app locale is aligned with that choice: while no language has been chosen explicitly, any locale pinned by an older installation is cleared, so changing the phone language later is picked up without reinstalling.
- Settings → Language contains an explicit **System language** entry, so a manual choice can be reverted instead of being permanent.
- Choosing a language still overrides the device language and is remembered.

## Discord linking and presence

- A successful token exchange could still leave the panel on "waiting for the Discord app" forever, because the SDK callbacks were awaited without any deadline. The connection now has a bounded deadline and reports "account linked, presence inactive" instead of spinning.
- The same bounded deadline covers restored sessions and the SDK-owned exchange path.
- When the presence connection drops or never becomes ready, Ketvoice retries with backoff (15 s, 45 s, 90 s) instead of freezing the panel, and re-sends the current track as soon as the SDK reports ready.
- The WebView reads the authorization code from the bridge page URL once it loads, so a custom-scheme navigation blocked by the WebView no longer loses the code. A **Terminer** action and an explicit message replace the silent stall.
- `DiscordCallbackActivity` initialises the SDK engine context before completing the authorization, which a cold start previously skipped.
- Rich presence is declared as **Listening** instead of Playing, matching a music player.
- The account state and the presence state are shown separately, with an amber indicator and a **Vérifier la présence maintenant** action when the account is linked but Discord is not ready. The diagnostic panel reports whether the SDK considers the session authenticated.

## Compatibility and validation limits

The signed Mobile and Quest APKs include the existing Discord integration. All 4.8.0 playback, search, backup, lyric, Home and restricted offline DASH behaviour is retained. Eleven interface languages remain available. Group listening remains deferred.

No phone or Quest was connected for this build. JVM/Robolectric tests, lint, signatures and checksums do **not** prove the real Discord authorization round-trip, Discord-side presence rendering, device-language switching on a physical phone, audible playback or physical Quest behaviour. The Discord fixes remove known stuck states and add visible diagnostics; a real owner-session check is still required, and Discord does not display your own presence buttons to you.

For update compatibility these APKs use the existing public Android debug signing identity, not a private production signing key. Never uninstall an existing installation to resolve a signature conflict without backing up its data.
