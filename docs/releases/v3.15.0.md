# Ketvoice 3.15.0

![Ketvoice](https://raw.githubusercontent.com/Tysnnn23/Ketvoice/main/ketvoice-banner.png)

## Lyrics — Apple Music sustained glow

- The sustained halo now starts after **820 ms** of continuously sung audio (was 870 ms). It is driven by the playback clock, so a 2 s word stays dark at 819 ms and lights only when the note is really held; 500 ms rap syllables stay completely clean.
- The glow is a **real blurred copy of the word's glyphs at two diffusion scales** (4–9 dp and 12–25 dp), drawn behind the letters. Because the blur acts on glyph alpha, light spreads outside the letters instead of a hard outline, `TextShadow` or a static blur.
- Fade in is ~300 ms, the hold keeps a subtle 2.6 s breathing cycle, and the exit fades over ~375 ms; the halo stays lit for the whole real word duration, then disappears. The sung fill also stops scaling (1.025×) so letters no longer drift.
- Only words declared at least 820 ms compose a glow node at all: unsung lines cost nothing, and the existing reduced-motion and high-performance switches skip the effect.

## Streaming and downloads

- Streaming and downloads now share **one persisted source priority** that includes the built-in sources: Ketvoice API MP3, Ketvoice API lossless, YouTube adaptive audio, then each custom manifest. Drag the handle in **Sources**; the order is stored on the device and applies to both playback and downloads.
- **Progressive off** (default): sources are tried strictly in that order and the first one that returns real audio bytes is used — no waiting for a better provider. **Progressive on**: sources are queried in parallel (4 at a time), the first validated stream starts immediately, and a better-ranked stream is prepared and swapped in without stopping playback.
- A resolved URL is no longer trusted blindly: a bounded HTTPS probe (with redirect and range checks) reads the first audio bytes and detects the real container (FLAC, MP3, AAC, Opus, WAV) before playback or download. A JSON error page or an expired provider is skipped instead of being handed to the player.
- Reads are now cancellable: when a source wins, the losing requests close their sockets instead of running to completion. The Ketvoice API and YouTube JSON calls, custom manifests and stream endpoints all use this path.
- Downloads start transferring as soon as the first verified source wins; the remaining sources are not awaited first. A second download request for the same track joins the running job instead of being rejected.

## Validation

- **277 debug and 233 release JVM tests** per variant cover the 820 ms envelope, 300/375 ms ramps, whole-word hold, breathing, diffusion growth, ordered-mode first-source stop, progressive-mode early start, failing/hanging sources, cancellation and source-order reconciliation, plus the glow node appearing only for held words.
- Live read-only checks: Ketvoice API search returned 40 tracks for "Lose Yourself Eminem"; `/stream?source=um` returned a **206 `audio/mpeg`** URL whose first 4 KB are real MP3 audio. `/stream?source=last` (lossless) still fails upstream — the ordered resolver skips it and continues.
- **Not validated**: physical phone or Quest playback, audible halo on hardware, download over a real network policy, and Discord. The host renderer used for screenshots does not implement `RenderEffect` blur, so the halo's blur intensity is a device-only result; the host test asserts that limitation instead of faking it.
