# Ketvoice 3.13.3

![Ketvoice](https://raw.githubusercontent.com/Tysnnn23/Ketvoice/main/ketvoice-banner.png)

## Discord: authorization inside Ketvoice

- The Discord consent page now opens in a WebView owned by Ketvoice. When it
  redirects to `discord-1566454532890820668:/authorize/callback`, the app
  intercepts the URL **before Android has to resolve it** and exchanges the code.
  This is the step browsers and the Discord app silently drop, which is why the
  panel never connected.
- No new redirect has to be registered in the Discord portal: the existing mobile
  redirect is used.
- Returning to Ketvoice without a code still cancels after 8 seconds, and the
  three-minute absolute timeout remains.
- A static `discord.html` bridge (`ketvoice://discord?...`) is deployed on the
  website as an additional path if a browser flow is ever needed.

## High quality that degrades honestly

- Lossless streams are probed before playback. A 4xx response (expired provider)
  hides lossless for 15 minutes instead of starting a dead stream, and the player
  uses the working MP3 immediately instead of waiting.
- Lossless is no longer allowed to delay playback: the first second and a half is
  reserved for it, then the fast MP3 starts and a later upgrade can still replace
  it when a real lossless stream arrives.
- Downloads retry the fast MP3 explicitly after the resolved candidates fail,
  before the YouTube fallback, and keep the actual downloaded format in their
  metadata.
- Settings explains that playback and downloads fall back to the fastest MP3 when
  the lossless source is unavailable.

## Validation

- Unit tests, release builds and lint run for both variants.
- **Not device-validated**: the WebView consent, the token exchange and the audited
  lossless fallback must be confirmed on the owner's phone. The third-party
  lossless provider itself is still expired; this release cannot renew it.
