# Ketvoice 3.16.1

![Ketvoice](https://raw.githubusercontent.com/Tysnnn23/Ketvoice/main/ketvoice-banner.png)

## Playback and downloads fixed

- **Root cause removed**: 3.15/3.16 sent an extra HTTP request to verify each stream *before* handing it to the player. Some CDN URLs are single-use or rate-limited per token, so that pre-request consumed the stream and left ExoPlayer buffering forever; downloads then reported "Aucun flux lisible". No pre-request is made any more: the provider URL goes straight to playback, and the downloader validates the bytes it actually writes.
- **Every enabled source is tried in cascade for downloads**, best quality first, instead of a single candidate. If the best URL fails, the next one is attempted before reporting an error.
- **The previous custom-source path is kept as a last resort** for both playback and downloads, so a manifest that worked before cannot be blocked by the new resolver.
- **No endless spinner**: playback resolution has a 25-second budget and always clears the spinner. Failures now say what happened ("Flux lent · réessayez", "Lecture impossible", "Aucune source activée · ouvrez Sources").
- If every source is disabled in the new Sources switches, the app says so instead of loading forever.
- Custom sources are initialised with the player, so their order and switches are available from the first track.
- Verification is now advisory only and cannot reject a stream for a CDN 403/429, an empty probe read or an unknown container. Only 401/404/410/451 (expired/gone) or an HTML/JSON error body counts as "unavailable".

## Validation

- 288 debug / 244 release JVM tests per variant, including a new decision-table test proving that 403/429/500/empty answers keep the stream while 410/404 and HTML/JSON pages reject it.
- Live diagnostic on the real API: `/stream?source=um` resolves and its URL returns MP3 bytes; YouTube adaptive resolves as AAC.
- **Not validated here**: playback and downloads on your phone/Quest. This build specifically restores the direct provider path, so if a source worked before 3.15 it should work again; the new logs/labels tell us which stage fails if not.
