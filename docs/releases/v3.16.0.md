# Ketvoice 3.16.0

![Ketvoice](https://raw.githubusercontent.com/Tysnnn23/Ketvoice/main/ketvoice-banner.png)

## Playlist

- The cover, title and controls scroll with the track list again, exactly like the album page. The header no longer stays pinned on screen, and it no longer reserves a faded empty block: scrolling shows tracks immediately under the top bar, and returning to the top restores the same artwork.

## Discord

- The unusable native "connect through the installed Discord app" path is gone. **Se connecter avec Discord** now always opens Ketvoice's own WebView OAuth window, which is the only account path offered. The panel states that no Discord password is requested or stored.

## Artist cache

- Artist pages (portrait, background, bio, listener count, tracks, albums, related artists) are cached on disk for 24 h, plus an access-ordered in-memory LRU; a cached artist renders immediately while a refresh happens in the background.
- Signatures, HD photos and backgrounds are persisted too, with HTTPS re-validation when read back. Failed lookups are cached for 5 minutes instead of being retried on every open, and broker timeouts drop from 10/18 s to 6/10 s.

## Downloads

- **Qualité de téléchargement** now has three honest modes: **FLAC · sans perte** (waits for lossless, then falls back), **Haute qualité** (keeps the best *actually available* compressed stream — AAC/Opus usually beat the 128 kb/s MP3 instead of silently downloading it), and **Rapide** (first readable source).
- Selection is based on the detected audio bytes and declared bitrate, not on which provider answered first. A completed source list is not made to wait for the full timeout, and quality modes query all sources in parallel even when progressive playback is disabled.

## Streaming

- Progressive playback now has a fallback: if the media session refuses the quality-switch command, the same track restarts at the current position on the better URL instead of silently staying on MP3.
- Playback starts on the first verified audio byte (no 30-second wait), ExoPlayer keeps filling its buffer, and the **next two queue tracks** are resolved and written into the audio cache in the background. This prefetch runs on unmetered networks, and on metered networks only when progressive quality is enabled.
- Playback and download each have their **own order and their own enable/disable switches** in Sources. The screen has a Lecture / Téléchargement selector; the list order is the priority order for that mode.

## Validation

- 285 debug / 241 release JVM and native-host tests per variant: playlist scrolls away without a blank area and restores identical pixels, separate playback/download orders, quality-aware download pick, cache round-trips for artist pages and artwork, HTTPS refusal on restored artwork, plus the existing glow and resolver suites.
- **Not validated here**: physical phone or Quest playback, the visible blur of the sustained lyric halo, real network downloads, WebView Discord consent end-to-end. Host rendering cannot evaluate `RenderEffect` blur, so that part remains device-only.
