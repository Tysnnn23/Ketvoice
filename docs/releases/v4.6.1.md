# Ketvoice 4.6.1

![Ketvoice](https://raw.githubusercontent.com/Tysnnn23/Ketvoice/main/ketvoice-banner.png)

## Lossless and Tidal playback

- Stream answers are parsed as `dash`, `flac`, `aac` or a direct URL, and now carry
  their declared `mimeType` and `codec`. `application/dash+xml` is recognised even
  when the proxy URL has no `.mpd` extension.
- An extensionless DASH manifest is played by Media3's DASH source. Previously the
  proxy URL was treated as one progressive file, which is the documented cause of
  buffering that ended in a pause. The manifest and its segments use the direct
  network source; the audio cache only stores complete progressive files.
- Encrypted or DRM-protected manifests are rejected. No DRM is bypassed and no
  Tidal credential, token or signed audio URL is logged. Media3 logging is routed
  through a logger that keeps only the HTTP status.
- The resolution budget is per source instead of one small global limit, so a slow
  hosted service can still answer after a fast provider started playback.

## Playback state

- Play and Pause pressed during resolution only change the requested state; they no
  longer restart a provider race or discard the pending item.
- A rejected quality upgrade leaves the audible stream untouched instead of
  restarting it, which used to interrupt playback mid-track.
- A real playback failure shows an explicit message and stops the spinner. One 401
  or 403 refreshes the same source before the player moves to another provider.
- Sources already tried are excluded from fallback, and the addon's own alternatives
  are attempted before giving up: a failing Qobuz match no longer hides Tidal.

## Lossless addon as the primary source

- `https://ketvoice-lossless.onrender.com/manifest.json` is added once on first run,
  placed first in playback order, and requests its `lossless` tier. Removing or
  disabling it is respected and it is never re-added.
- A lightweight keep-alive request runs about every ten minutes while the app
  process is alive. Android may defer it under Doze or stop it when the app is
  force-stopped; an exact ten-minute schedule while the app is closed is not
  guaranteed.
- Prefetched next tracks reuse only the stable, unsigned `.onrender.com` DASH proxy
  URL, for at most one minute and only while that source stays enabled. Signed URLs
  are never stored for a later resume.

## Compatibility

Local files, downloads, cache, Bit-Perfect, gapless, crossfade, synchronized lyrics,
Canvas, the mini-player, the restored navigation and the Quest landscape layout are
unchanged. Eleven interface languages remain bundled. Group listening remains deferred.

## Validation limits

Recorded validation covers JVM/Robolectric tests, host fixtures, lint, signature and
16 KB alignment checks, and separately measured service responses. The hosted addon
returned HTTP 200 for stream resolution, HTTP 200 for an unprotected DASH manifest and
HTTP 206 for the first media segment. That is not proof of audible playback on a phone.

Not validated: installation on a physical phone or Quest, real GPU rendering, USB DAC
or bit-exact output, and audible Tidal playback end to end. No frame-rate or fixed
start-up time is claimed. The optional `/search/fast` addon endpoint is prepared but
not deployed by this release; the app falls back to the existing aggregate search.

Source, APK signatures and checksums are recorded in `validation.json`. The signing
identity is the existing public Android debug certificate kept for update compatibility.
