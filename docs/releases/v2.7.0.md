# Ketvoice 2.7.0 — Mobile-style Quest window and music-upload fix

**versionCode 15 · 22 October 2026**

## Download the right APK

- **Ketvoice-2.7.0.apk** — phone/tablet build, Android 12+.
- **Ketvoice-2.7.0-Quest.apk** — Quest 3/3S Android-window build, Android 12L+.

Both use the existing development signing certificate and package name. They can update the previous app without uninstalling; they do not install side-by-side on the same device.

## Quest: the mobile UI, not a new dashboard

- Reuses the **original mobile player and floating navigation**: same artwork/Canvas treatment, icon controls, transitions, gestures, synchronized lyrics, and Liquid Glass. No oversized Quest toolbar, tablet navigation rail, or forced two-column player.
- A portrait default window and bounded content preserve phone-like proportions even when the panel is resized wide.
- Optional lyric sizing and playback keep-awake live in ordinary Settings. A 15/30/60-minute sleep timer lives in the normal track ⋯ menu; it can be cancelled there.
- Original control sizes are preserved. Subtle pointer hover/focus feedback is added without replacing the visual design.
- Headset manifest declares Quest 3/3S, optional touchscreen/faketouch, a resizable panel, and 64-bit ARM support. This is a **2D window**, not an immersive 3D environment.

See [Quest installation and limitations](https://github.com/Tysnnn23/Ketvoice/blob/main/docs/QUEST.md).

## Music publication fix — already deployed server-side

Logs showed audio and cover uploads succeeding, followed by a `SyntaxError` and rollback. An associated lyrics INSERT returned **HTTP 201 with an empty body** (PostgREST's normal `return=minimal` behavior). The broker incorrectly tried to parse that body as JSON.

The database-response helper now accepts empty successful responses. Regression tests reproduce the old 500 and pass with the fix, including songs with lyrics/cover, songs without lyrics, legacy 204 responses, and rollback on a genuine database failure. **Existing 2.6.1 clients also benefit from this server fix.** Server-side publisher authorization, rights confirmation, size/signature checks, and public content behavior remain unchanged.

## Limitations

- **No physical Quest was available.** This is a headset-targeted build with emulator validation, not a claim of exhaustive hardware compatibility, Meta Store approval, or guaranteed headset FPS.
- The mailbox owner still needs to retry their own real music upload. No mailbox login was impersonated, and no test song was published to the live catalog.
- The timer is process-local; force-stopping/restarting the app cancels it. Expiry arithmetic is unit-tested; a full 15-minute wait is not claimed as a runtime test.
- Existing email rate limits, upstream service availability, and public-media storage/egress quotas still apply.
- Existing informational unused-index advisories were left unchanged. Supabase's existing [leaked-password protection warning](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection) is unrelated to this passwordless publication fix.
- The previous 2.6.1, 2.6.0, and 2.5.0 releases remain unchanged. Historical 1.2.0–2.3.0 APKs remain withheld.
