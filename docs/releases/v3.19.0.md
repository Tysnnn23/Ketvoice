# Ketvoice 3.19.0

![Ketvoice](https://raw.githubusercontent.com/Tysnnn23/Ketvoice/main/ketvoice-banner.png)

A feature pass on top of the 3.18.0 design system. Still code-only — CI now
builds the APKs for you (see below), so this tag can produce signed artifacts
automatically.

## Dynamic colour that follows the music

- **Theme now breathes with the now-playing artwork.** A new cover-palette
  extractor samples a downscaled bitmap, quantises it into colour buckets and
  picks the most vivid colours that also stay legible as an accent — then feeds
  them into the whole UI as the accent colour. It is cached per artwork URL so
  switching tracks never stutters, and it is opt-in via the existing **Album
  colours** setting.
- Colours are clamped into a legible band (not too dark, not too bright) so text
  and icons on the accent always read.

## "Ton récap" — listening stats

- New **Ton récap** screen (Wrapped-style): total time listened, number of
  plays, unique artists, the most-replayed track, top artists and top tracks —
  all derived from the listening history already stored on the device.
- **100% offline**: nothing leaves the phone. A shareable one-line recap is
  available for the OS share sheet.
- Stats are recomputed incrementally whenever a track is recorded, so the screen
  opens instantly.

## Accessibility & polish

- The stats cards use the shared design tokens (elevation, contrast-aware text),
  so they respect light/dark and large windows automatically.

## CI: APKs are built automatically

- Added a **GitHub Actions** workflow (`.github/workflows/android.yml`) that, on
  every push and on version tags, compiles the app, runs the unit test suite,
  lints, uploads the APKs as build artifacts, and **attaches them to the GitHub
  Release when a `v*` tag is pushed**.
- This means the 3.18.0 gap ("no APK in the release") is now filled by CI: tag a
  version and the workflow produces the mobile + quest release APKs and attaches
  them.

## Validation

Changes are additive (new screen, new palette object, CI file, version bump). The
Gradle build and on-device checks are delegated to the new CI workflow; they were
not run in the environment where this commit was authored (no JDK / Android SDK).
