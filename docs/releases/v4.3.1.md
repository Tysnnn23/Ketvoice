# Ketvoice 4.3.1

![Ketvoice](https://raw.githubusercontent.com/Tysnnn23/Ketvoice/main/ketvoice-banner.png)

## Ten languages stop falling back to French

- 116 user-facing strings existed only in French, so German, Spanish, Japanese,
  Korean and the other nine languages showed raw French on those screens. They
  are now written by hand in every table: playback and source ordering, the
  Bit-Perfect status panel, download queue and Wi-Fi states, updater errors,
  Discord diagnostics, the listening recap and share actions.
- Placeholders, brand names and units are preserved exactly, so composed labels
  still reorder their arguments per language and `Hz`, `Bit-Perfect`, `GitHub`
  and `{0} min` keep their original form.
- Strings that only look like UI copy — structured log fields, `Accept-Encoding`
  and `Cache-Control`, cache keys such as `artist:{0}:{1}`, Compose animation
  tags and `.apk`/`.fileprovider` patterns — stay out of the catalogs on purpose.
  They are listed with a reason in `tools/ui-text-ignored.json`.
- The catalog now holds 1065 messages per language. French remains the default
  among the eleven interface languages; no layout, navigation or playback
  behaviour changed in this release.

## The gap cannot reopen unnoticed

- `tools/audit_ui_texts.py --check` scans the UI and message sources and fails
  when a user-facing string has no bundled translation, and also when an allowlist
  entry goes stale because it was finally translated. CI runs it on every push.
- `tools/complete_ui_translations.py` no longer overwrites the shipped catalog.
  It drafts into `tools/machine-translations.proposal.json` and needs `--apply`
  after a human review, because that output is not shippable: it renders
  "Reprendre" as *Lebenslauf* / *Currículum* / *이력서*, "DISCORD" as *不和谐*
  and prefixes some Chinese values with `#`.
- `docs/TRANSLATIONS.md` documents the workflow, including the rule that
  `UiTextDictionaryTest` enforces identical key sets, non-empty values and
  placeholder preservation across all ten tables.

## Downloads that survive the process

- The download queue is now persisted to `files/download-queue.json`. A paused
  transfer comes back paused after the app is killed, a pending one restarts on
  its own, and a failed entry stays visible without holding a busy slot.
- Cancelling or deleting an entry removes it from the stored queue, and entries
  whose file already exists are pruned at load. Capsule downloads never enter the
  queue.
- A restored transfer restarts its bytes from zero: the queue entry and its state
  survive, partial file bytes do not.

## One stable signature for every APK

- Every CI build is signed with the same pinned certificate, so a new APK installs
  over the previous version instead of being refused as a conflicting package.
- The keystore secret is decoded with whitespace stripped and validated against a
  pinned certificate digest before compiling, and each built APK is re-checked
  after the build. A corrupt secret or a wrong-identity APK fails the run loudly
  instead of shipping.

## Validation and remaining limits

- Mobile and Quest JVM suites pass (1264 tests across the four variants, 0
  failures), lint reports no errors, and both release APKs are verified for
  package, version, ZIP integrity, 16 KB alignment, non-debuggable manifest and
  the pinned signing certificate. Exact counts and checksums are recorded in the
  release's `validation.json`.
- No phone, emulator or physical Quest was connected for this release, and an
  emulator boot was not possible locally for lack of free disk space. On-screen
  rendering of the new translations, real install/launch, USB DAC negotiation,
  hardware glass/Canvas, gesture feel, 60/90/120 FPS, live audio providers and
  Discord consent/presence remain unvalidated.
- Group listening remains deferred. Publishing and editing authorization is
  unchanged and still server-enforced for the verified owner account.
