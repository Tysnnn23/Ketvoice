# Ketvoice 4.0.1

![Ketvoice](https://raw.githubusercontent.com/Tysnnn23/Ketvoice/main/ketvoice-banner.png)

## Album page: full-bleed artwork, Canvas or cover

- The square artwork card is gone. The album visual now runs **edge to edge**: no
  side margins, no rounded rectangle, and the **album colour washes the top of
  the page** before fading into the background.
- A new **Apparence → « Canvas sur les pages d'album »** switch shows the album
  Canvas in that full-width area when one exists, and the cover otherwise. It is
  **independent from the player's Canvas setting**, so disabling one keeps the
  other.
- The Canvas is resolved for the album's first track and respects reduced motion
  and high-performance mode (falls back to the cover). The title, artist, year,
  track count, duration and the Écouter / Aléatoire buttons stay below the visual.

## Icons and launch animation

- **Themed icon**: every launcher variant (default, glass, dark, classic and
  round) now has an Android 13+ **monochrome layer**, so Ketvoice follows the
  wallpaper palette when the system is set to themed icons.
- **Animated splash**: Android 12+ uses a matching system splash, then the
  in-app mark springs in with the wordmark before fading into the app. Reduced
  motion shows the final frame immediately.
- The icon-variant setting keeps working: the chosen icon is applied at launch
  and the splash always matches the light icon canvas.

## Build and packaging fixes

- **Duplicate imports in `app/build.gradle.kts`** (introduced by the signing
  commit) made `main` fail to configure. They are removed, so the repository
  builds again.
- **CI signing guard**: the v3.19.0 tag published APKs signed with a throwaway
  debug key (`CN=Android Debug`), which Android rejects as a package conflict.
  The workflow now attaches release APKs **only when the stable
  `KETVOICE_KEYSTORE_B64` secret is available**, and it no longer overwrites
  existing assets.

## Discord

- The account panel gains a **Diagnostic Discord** section showing link/presence
  state, the last SDK line, the redirect and the scope, with **Copier le journal**
  and **Relancer la connexion**. That journal is what identifies the remaining
  failure (callback not received, token exchange error, or presence start).
- The PKCE exchange, persisted pending state and callback parsing from 3.17
  remain in place; a live check against Discord's token endpoint still confirms
  the client id, redirect and request shape.

## Validation

- Android JVM and native host tests, including a new regression test that the
  album visual starts at 0 px and reaches the full window width, plus a screenshot.
- Signed Mobile and Quest builds with the stable certificate, lint with zero
  errors, credential scan with zero findings, and public download hashes verified
  after publication.
- **Not validated on a physical phone/Quest**: the Canvas decoding inside the
  hero, the Discord consent with a real account, and the final visual animation
  feel. Host rendering cannot decode video or evaluate blur.

## From the 4.0 proposal list

- **Dynamic cover colour**: kept — the palette is sampled from the artwork and
  drives accents, the album hero wash and the player chrome.
- **Cover → player transition**: kept — the artwork flies between the mini-player
  and the player, with reduced-motion fallback.
- **Morphing mini-player**: kept — the chrome condenses while scrolling and
  returns to the full presentation when you scroll back.
- **Download manager**: per-track progress percentages, the artwork progress
  ring, active downloads in the list and the global progress bar are all live.
- **Adaptive icon + animated splash**: new in this release (above).

Still future work, not part of the requested five: pause/resume/priority queues
for downloads, a fully custom icon pack, unified search tabs and smart playlists.
