# Ketvoice 3.13.1

![Ketvoice](https://raw.githubusercontent.com/Tysnnn23/Ketvoice/main/ketvoice-banner.png)

## Discord linking fixed

- The authorization redirect is now received by Ketvoice's own exported activity.
  The SDK helper could return without calling back when the Discord app handed the
  user back to Ketvoice, which left the panel stuck on "Connecting to Discord…".
- Ketvoice runs the OAuth2 + PKCE flow in a browser tab and passes the returned
  code to the SDK for the token exchange. `state` is generated and checked locally;
  the code challenge uses S256 and only the verifier stays in memory.
- A three-minute timeout now clears the busy state instead of spinning forever,
  with explicit messages for a canceled authorization, an invalid response, a
  timeout and `invalid_client` (which points at the portal's **Client public**
  setting).
- Presence still appears only after linking, while a track is actually playing,
  and is cleared on pause, stop, unlink or opt-out. No password, user token or
  self-bot is involved.

## Language default

- Ketvoice now starts in the user's system language when it is one of the eleven
  supported languages, and in English otherwise. French is no longer forced for
  new installs.
- Picking a language in Settings is remembered as an explicit choice; clearing the
  app data returns to the system language.

## Validation

- Unit tests cover the PKCE challenge against the RFC 7636 example, verifier and
  state generation, the authorization URL and the presence payload rules.
- The 3.13.0 Discord runtime is unchanged apart from the redirect receiver.
- **Still not device-validated here**: no phone, Quest or accelerated emulator is
  available in this environment. The browser redirect, token exchange and presence
  must be confirmed on the owner's phone with a second Discord account.
