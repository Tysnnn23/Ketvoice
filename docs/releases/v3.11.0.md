# Ketvoice 3.11.0 — smoother playback and artist portraits

**versionCode 56** — signed Mobile and Quest packages with the existing update certificate.

## Readable menus and a calmer dark theme

Dark player action sheets now keep their own dark surface when opened above a
light page. Titles and actions no longer disappear as white text on a white
panel. Rounded sheets respect system-bar space. The dark palette uses charcoal
surfaces, clearer elevation and brighter secondary text, with explicit Material
surface and outline colors. Normal Canvas clips remain fully fitted, now with
rounded video edges rather than a hard rectangular cutoff. Their original
frames are not cropped or faded to hide the problem.

## Continuous player transitions

Canvas fullscreen entry/exit crossfades, and its controls fade and slide rather
than disappearing abruptly. Tap the image to hide or reveal the controls; Close
or Android Back exits fullscreen. Controls hide after inactivity during playback
and remain available when paused. Seeking does not dismiss the Canvas.

Lyrics transport controls stay mounted through their exit animation, return
smoothly, and share a moving viewport boundary with the expanded lyrics. Sheet
entry and track-menu dismissal also transition smoothly. Reduced-motion settings
remain respected and do not disable karaoke synchronization.

## Portrait-led artist profiles and optional signatures

Artist profiles feature a larger portrait, a long fade into the page and a
centered identity area, without replacing Ketvoice navigation. Wide catalogue
banners remain fitted rather than arbitrarily zoomed. Long names stay readable.
Settings → Appearance adds an opt-in artist-signature switch, disabled by default
including for upgrades from the old unused setting. Artist names are sent to the
signature service only while this option is enabled. Known public-domain assets
retain source attribution; missing, rejected or unavailable images fall back to
the normal name. SVG decoding and raster ink/white-paper handling are supported.

## Native 120 Hz request on supported phones

Settings → Appearance adds a separate 120 Hz option. It selects a native mode
reported by the current display at the same resolution, including fractional
120 Hz panel clocks. It does not pretend that 60/90 Hz hardware supports 120 Hz.
The window preference is restored when disabled, paused, disposed or in battery
saver. The current display refresh rate and request status are shown separately.
Android may cap the rate; this is not a guarantee of 120 rendered frames per
second and can use more battery. Quest retains its platform-managed refresh rate.

## Timed backing vocals and automatic updates

Timed backing vocals are fully hidden before their own native timing window,
fade out when it ends or the next lead line starts, and keep measured space to
avoid scroll jumps. Line-only lyrics use their parent line's active interval;
untimed text does not invent word timings. AutoMix remains absent from playback,
settings and interface; only upgrade cleanup of retired data remains.

The automatic update popup remains enabled with release notes and a trusted
repository banner when the release includes one. There is no required manual
check on a functioning updater. Android still requires installation permission
and confirmation; silent APK installation is not supported. Older builds with
the previously broken updater may still need a one-time GitHub install.

## Validation and limitations

Validation metadata records JVM and host Android/Skia checks, UI clock/state
fixtures, live signature metadata checks, lint, APK identity/signature/alignment,
credential scans and public download checksums. Signature image availability is
external; the asset host returned HTTP 429 during a live check, so that is not
reported as a successful in-app live image download. Local SVG/raster fixtures
verify renderer behavior, not an owner session.

No physical phone, physical Quest or emulator validation is claimed. Real GPU
transitions, sustained 120 Hz/FPS, battery consumption, actual install-permission
return, APK upgrade installation and signed-app live downloads remain untested.
The website is synchronized from the pushed checkout and real public release
feed; local browser checks are distinguished from production-host deployment.
Concurrent local `MainActivity.kt` work is excluded. No group listening is added.
