# Ketvoice 4.1.0

![Ketvoice](https://raw.githubusercontent.com/Tysnnn23/Ketvoice/main/ketvoice-banner.png)

## Instant playback: every source races for the first stream

Starting a track used to be a sequential business: the resolver asked one
provider, waited for it to answer (up to ~14 s), then tried the next one, and
only returned a stream once the whole chain had been walked. On a phone with
three or four sources enabled, that is the difference between "the music starts"
and "the music starts after I already gave up".

- **All enabled sources are now queried in parallel.** The first usable stream
  wins and playback starts immediately, instead of waiting for the slowest
  provider in the chain.
- **Quality is no longer a blocker.** The best stream (FLAC / highest bitrate)
  keeps loading in the background and takes over the *already playing* item at
  the same position, so a fast start no longer costs you audio quality.
- **The « qualité progressive » switch changed meaning**, not behaviour: it only
  decides whether a *better* stream is fetched at all. It no longer gates the
  fast start, nor the seamless handoff — those are always on now.
- A single `TOTAL_RESOLVE_BUDGET_MS` (25 s) bounds the whole resolution pass, so
  a dead provider can never leave an endless spinner.

## Queue look-ahead

- The **next two tracks of the queue** are resolved ahead of time, so skipping
  and auto-advance feel instant instead of paying full resolution latency.
- Look-ahead now also runs on **metered connections**: the stream is resolved so
  the handoff is ready, and only the *byte caching* is skipped to protect your
  data plan.
- Error recovery uses the same raced resolution (with the failed URLs excluded),
  so a provider going down costs one retry, not a hang.

## Album page compile fix

- The full-bleed hero introduced in 4.0.1 called `clipToBounds()` **without
  importing it**, which broke the Kotlin compilation. The import is restored.

## Validation

- CI on `main`: `assembleMobileRelease` + `assembleQuestRelease`, unit tests and
  lint all green.
- **Not validated on a physical phone/Quest**: the perceived start latency
  against real providers, and the audible seam (or absence of it) during the
  background quality swap. Both depend on network conditions that the CI cannot
  reproduce.

## Notes

- Signed APKs are attached to the release only when the stable
  `KETVOICE_KEYSTORE_B64` secret is present, so they install over your existing
  Ketvoice without a package conflict.
